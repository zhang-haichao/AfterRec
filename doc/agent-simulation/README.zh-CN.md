# AfterRec Agent 模拟环境技术设计

[English](README.md)

修订稿 · 2026 年 11 月 20 日

本文描述 AfterRec 模拟环境的拟议实现。仓库已包含最小模拟运行器与行为类型，浏览器原型和独立 BPR 推理在本仓库之外验证。下文给出的环境接口、事件格式和服务路由供后续开发与联调使用。示例 ID 均为虚构。

[项目架构](../../docs/architecture/OVERVIEW.zh-CN.md) · [共享模拟协议](../../docs/research/SIMULATION_PROTOCOL.md)

首版让 Agent 按推荐模型给出的顺序逛商品列表。每轮先展示一页商品，再由 Agent 决定看哪些、如何评分、继续还是退出。环境负责执行和记录，页面根据同一份记录展示实时过程和历史回放。以后可以换推荐模型、换 Agent，或增加更细的动作。

## 1 环境由哪些部分组成

| 部分 | 负责什么 |
| --- | --- |
| 推荐接入 | 调用推荐模块获取给某个用户的有序商品榜单。也支持用导入榜单联调。重训和遗忘后的模型经同一接口提供推荐。 |
| 会话执行 | 环境保存当前轮次、这一页商品、已执行动作和结束原因。运行器按顺序调用推荐、Agent 和环境，处理进度、超时与取消。一次运行可以包含多场会话，每场对应一个用户和一个模型组。 |
| Agent 适配器 | 把当前可见商品和行为历史传给规则 Agent、本地模型或远程模型，转换它们的回答。环境负责核验回答后执行。 |
| 轨迹存储与展示 | 保存每轮看见的商品、动作和结果。前端从事件更新画面，回放和指标计算使用同一份记录。真人记录通过单独的导入器进入回放。 |

**已验证的原型**。浏览器原型能导入排序榜单、运行规则 Agent、播放同次模拟并导出 JSON。UserArena 真人轨迹可导入和回放。示例榜单用于演示，真实 BPR 推理已在独立的 RecBole 命令行作业跑通。大模型调用流程用模拟响应验证过。

**首版后端要补齐**。接推荐模块的服务，把任务运行、动作校验和轨迹保存放到服务端，并验证真实 Agent。沿用 AfterRec 的 FastAPI、Pydantic 和 Python 模拟骨架，复用已有回放逻辑。推荐模块继续用 RecBole 加载模型和打分。 [AfterRec 共享接口](../../docs/contracts/INTERFACES.md) · [模拟运行器](../../backend/src/recforgetbench/simulation/runner.py) · [RecBole](https://github.com/RUCAIBox/RecBole)

## 2 推荐模型怎么接入

运行器用 `model_id` 定位已登记的模型产物，环境调用 推荐模块的 `recommend(user_id, top_k, state)`。输入是用户 ID、需要的商品数和会话反馈，输出是按名次排列的商品 ID、推荐分数和可选的商品资料。模型对应的 ID 映射、物品目录和候选规则由推荐模块提供。

```text
model_id=bpr-01, recommend(user_id=u01, top_k=4, state={})
→ [{"item_id":"p01","rank":1,"score":0.82}, {"item_id":"p02","rank":2,"score":0.71},
   {"item_id":"p03","rank":3,"score":0.68}, {"item_id":"p04","rank":4,"score":0.56}]
```

**固定榜单是首版默认策略**。每场开始请求一次。比如计划最多看 2 页、每页 2 件，就请求 4 件并保存返回顺序。继续浏览时直接从榜单取下一页。后端方案允许展示不足一页的尾页，榜单为空则结束并记录 `no_items`。模型找不到用户或调用失败时记录具体原因。首版可以单独评测原模型（Original）。重训模型（Retrain）和遗忘模型（Unlearned）可用后，三组对照使用相同的候选规则和浏览预算，各自创建会话与 Agent 记忆。模拟期间默认固定模型参数。

**后续可加入反馈推荐**。如果选用反馈策略，下一页开始前把已确认的点击、反感反馈或已看商品交给推荐模块，由它返回下一页的新顺序，轨迹分别记下原始名次和实际展示名次。每次运行保存推荐策略及版本，便于知道结果是在什么条件下产生的。固定和反馈两种策略各自决定下一页的来源。删除意图和商品关联标签分别供 Agent 访谈和评测使用，推荐接口沿用约定的会话反馈。 [AfterRec 推荐契约](../../docs/contracts/INTERFACES.md#recommendation)

## 3 Agent 能做什么以及画面怎么变

首版每页向 Agent 要一次决定。决定里包含本页要看的商品、评分（如适用）以及看完后继续还是退出。环境先整体验证，再一次提交。下面以同一场会话的两页商品为例。

| 行为 | 环境与展示如何处理 |
| --- | --- |
| 查看或点击 | 只允许选择本页商品。环境记录打开的商品，页面按决定中的顺序展示详情，再回到商品列表或直接进入下一页。 |
| 给商品评分 | 原模型模式中，已查看商品可给 1–5 分。评分跟对应商品一起保存，页面在详情或商品卡上显示。推荐分数由推荐模块给出，商品评分由 Agent 给出。 |
| 跳过或继续 | 可以一件也不看就继续。环境取出下一批商品并更新页面。旧遗忘对照的「跳过」归入这种情况。 |
| 退出或结束 | 主动退出、达到页数上限或榜单耗尽时结束浏览。保存原因，按模式采集满意度或访谈回答。满意度是整场体验的 1–10 分。 |

例如，Agent 在 `[p01, p02]` 这页选择打开 `p01`、打 4 分、继续。前端依次显示第一页、`p01` 的详情和评分、第二页 `[p03, p04]`。详情画面是把同一页决定依次展开，轨迹记为一次页级决定。旧遗忘对照的点击可转换成一次查看，缺少的评分留空。

**动作的扩展方式**。以后需要在详情页继续决策，或支持返回、反感反馈、加入购物车，再给环境新增对应状态和动作。每种动作都要定义需要的参数、在哪种画面可用、成功后进入什么状态、怎样记日志。逐个动作决策时使用单独的动作版本和动作预算，避免把「一次整页决定」和「一次点击」合并为同一种计数。

## 4 不同 Agent 怎么用同一个接口

**运行器 → Agent 适配器**。`AgentPolicy.act(observation)` 传入观察编号 `observation_id`、用户画像、当前可见商品、已执行动作和该次决策的规则，返回一份候选决定。规则 Agent 可直接返回，大模型适配器负责组织请求并解析响应。结束问答另走一个阶段，按实验模式请求满意度、开放回答或提示后回答。

```text
observation_id=o1, items=[p01,p02], action_schema=page_v1
decisions=[next,exit], rating_range=[1,5]
→ {"viewed":[{"item_id":"p01","rating":4}],"decision":"next","comment":"想继续看看"}
```

观察只包含当时可见的商品和已发生的动作。模型组别和商品关联标签保存在运行或评测记录中。对照实验采用相同的画像和提示词规则。新增 Agent 时登记模型、提示词版本和支持的输入类型。支持图片的 Agent 可以接收当前画面的图片引用，仍按同一动作约定返回。超时、格式错误和非法动作按运行配置有限重试，失败时保留原因和已提交轨迹。

**运行器 → 环境**。`reset(config, user_id, model_id)` 初始化会话并返回第一页观察。`step(trace_id, observation_id, action_id, decision)` 检查页号、重复商品和评分范围，再把生效事件和新状态一起保存。返回已提交事件与下一页观察或结束原因。同一动作编号原样重试时返回原结果。用同一编号提交不同内容，或针对旧页面执行动作，都会报错。提交前再次检查运行是否已取消。

```text
reset(config=run_config, user_id=u01, model_id=bpr-01) → trace=t01, observation=o1
step(t01, o1, a01, viewed=[p01:4], decision=next) → event_seq=2, observation=o2
```

## 5 轨迹怎么记录并用于实时展示和回放

首版记录三类事件。`page_shown` 在询问 Agent 前保存实际展示的商品及顺序，`page_decided` 保存生效的整页决定，`session_ended` 保存结束原因和会话级结果。访谈回答按问答阶段保存。每条事件用 `trace_id` 找到会话，用 `seq` 确定播放顺序。错误和被拒绝动作进入诊断记录。

```json
{"trace_id":"t01","seq":2,"type":"page_decided","observation_id":"o1",
 "viewed":[{"item_id":"p01","rating":4}],"decision":"next"}
```

`seq=1` 是同场 `o1` 的曝光事件，保存了 `[p01, p02]`。前端收到 `seq=2` 后可以展开 `p01` 的详情和评分。收到下一次曝光再换列表。实时展示和历史回放用同一套规则。刷新后按会话和最后读到的 `seq` 补读，回放读保存的商品快照和事件。

| 接口或产物 | 约定 |
| --- | --- |
| 启动与查看 | 前端调用 `POST /api/v1/simulation-runs`，提交模型、用户、Agent、最多页数 `max_pages` 和每页条数 `page_size`，获取 `run_id`。用运行 ID 查看状态、轨迹与结果引用。读取轨迹时传 `trace_id` 和 `after_seq`。这些路由属于后端拟定方案。 |
| 运行目录 | `config.json` 保存模型产物 ID、数据集版本及切分版本、遗忘清单 ID（如适用）、Git 版本、Agent 和提示词版本、种子、预算及推荐策略。`traces.jsonl` 保存有序事件，`metrics.json` 保存指标与样本数。三份文件由同一 `run_id` 关联。 |
| 兼容旧记录 | 按 `schema_version` 读取。浏览器导出的 `rounds` 通过转换器生成回放事件，需要用到新字段时保留缺失。以后加入新的动作或指标，分别登记动作和评测协议版本。 |

## 6 真人轨迹从哪里来以及怎样处理

真人回放接 UserArena 官方 `data/sessions.jsonl`，现有原型已经读入其中 535 个会话。文件每行是一场会话，`session_id` 是会话编号，`feed_catalog` 是商品资料，`trajectory` 是按发生顺序排列的动作与观察记录。另保留通用 JSON 导入入口，换数据源时通过转换器统一格式。 [UserArena 数据说明](https://github.com/RecGPT-Team/UserArena#data-and-environment)

```text
输入示例：action=scroll_down, scroll_top=0, scroll_delta_px=320
转换结果：type=scroll, direction=down, offset_before_px=0, delta_px=320
```

示例中的用户从 0 像素处向下滚动了 320 像素。本步按 `visible_items` 展示动作前看到的商品，动作后的画面由后续记录提供。`gui_image` 是该步的重建截图，`feed_long_image` 是会话的整页长图。没图时用商品资料还原，缺少时间时按步骤等间隔播放。保留原始动作名和文件来源，便于检查转换。UserArena 源数据按非商业研究许可单独获取，本仓库使用虚构例子。 [UserArena 数据许可](https://github.com/RecGPT-Team/UserArena/blob/main/LICENSE)

真人与 Agent 并排回放用于观察行为差异。计算动作频率或行为相似度前，先选任务和商品场景可比的会话，并统一动作粒度。只有曝光画面的记录可以播放，统计行为时按实际动作计数。

## 7 开发顺序与评审事项

| 阶段 | 工期 | 验收 |
| --- | --- | --- |
| 1 对齐接口 | 1 天 | 和推荐、遗忘模块定好模型产物、候选规则与榜单字段，用四件商品做统一联调例子。 |
| 2 接通首版 | 3 天 | 先用文件榜单和规则 Agent 跑通，再接推荐模块的 BPR。检查商品顺序、评分、翻页和退出。 |
| 3 保存与回放 | 3 天 | 运行中和历史回放呈现相同轨迹。验证重复动作、刷新补读、取消和真人视口顺序。 |
| 4 扩展联调 | 3 天 | 接一个真实大模型，验证超时和异常响应。遗忘模块的产物就绪后做三组对照和指标复算。 |

按一人开发初估 10 个工作日。评审先确定候选过滤、首版允许动作和真人对照口径，再决定反馈重排和详情页逐动作决策的开发时机。
