# 推荐模块与 Agent 模拟模块接口约定

[English](RECOMMENDATION_AGENT.md) · [文档目录](../README.zh-CN.md) · [模块设计](../modules/agent-simulation/DESIGN.zh-CN.md)

**接口状态：** 拟议，待推荐与模拟两方确认。下表分别标明仓库已有接口、本地原型和拟议交接。

## 1. 对接场景

研究者选择用户和原模型后，**推荐模块**提供该用户的有序商品榜单，**模拟模块**消费榜单并运行购物会话，**实验平台**按运行 ID 保存并读取结果。推荐方负责排序，Agent 负责选动作，模拟环境负责验证和记录。真人回放直接读取外部会话文件，独立于这条推荐调用链。

## 2. 调用方式与输入输出

| 接口或产物 | 输入 | 输出 |
| --- | --- | --- |
| 取榜（已有 Python 协议）`recommender.recommend(user_id, top_k, state)` | 已加载并冻结的模型、用户 ID、所需数量、会话反馈 | 按名次排列的 `RecommendedItem` 序列，含稳定商品 ID、原始分数和名次 |
| 装入购物环境（本地浏览器接口）`beginAgent({products})` | 有序商品数组。每件须有唯一非空字符串 `id`（对应 `item_id`）、非空名称 `name`、非负数值价格 `price` | 新会话的首个观察。联调时原始榜单随会话留存，商品展示资料按 ID 关联 |
| 逐步交互（本地浏览器接口）`observe()`、`act(action)` | 读取页面后提交一个动作。评价须指定当前详情商品和 1–5 星 | 成功返回生效事件，可再读取更新后的页面。非法动作返回原因，页面与事件序列保持原状 |
| 轨迹交付（本地文件，平台归档为拟议）`exportTrace()` | 当前购物会话 | 带商品快照和有序事件的 `afterrec.objects.v1` JSON。拟由平台关联运行 ID、用户 ID 和模型 ID，交给回放与评测使用 |

浏览器方法由 `window.afterrecStore` 提供。例如 `window.afterrecStore.beginAgent({products: [{id: "P17", name: "台灯", price: 99}]})` 可用一件商品启动本地会话。

**调用时机。** 仓库现有 `run_episode` 每一步都会调用推荐器。本期购物模式拟在会话开始时取一次榜单，打开详情、评分和返回都复用该榜单。适配层按 ID 补商品价格等展示所需资料，保留原始顺序。真实榜单缺少必要资料时，应指出缺失的商品及字段。

**观察与动作。** 浏览器的 `items` 表示当前页面的结果，`inViewport` 标出此刻滚动窗口内的商品。拟接入的 Agent 只接收当步可见信息、获准使用的画像和已执行动作。仓库现有 `AgentAction` 覆盖点击、不喜欢、跳过和退出。打开详情、评价和返回使用购物动作版本。后端接入时须保留动作版本与来源，供回放和统计选用。[共享类型与方法](../contracts/INTERFACES.md) · [仓库运行器](../../backend/src/recforgetbench/simulation/runner.py)

**最小联调例。** 推荐方返回 `P17` 第 1、`P42` 第 2。模拟方按此顺序展示两件商品，打开 `P17` 后提交 `{type: "review", id: "P17", stars: 4}`。预期得到一条对应 `P17` 的评价事件，当前页面仍是 `P17` 详情。返回后列表保持原顺序。
